# RSFX 1.1 — ASR-10 / ASR-X style effects for the MPC

One VST2 effect plugin for your rooted Gen1 MPC (32-bit ARM) with 98 algorithms, selected with one knob:

- **50 ASR-10 ROM effects**, named and ordered as in the ASR-10 Musician's Manual (`10:` prefix)
- **40 ASR-X / ASR-X Pro insert effects**, as listed in the ASR-X Pro Reference Manual (`X:` prefix)
- **8 ASR-X global reverbs** (`XG:` prefix)

These are **approximations**, not recreations of Ensoniq's DSP code. The algorithm names, structure and
parameter ideas come from the manuals; the sound comes from published, generic DSP designs. Nothing has been
compared against a real ASR-10 or ASR-X yet. `docs/SOURCES.md` says where each decision comes from.
RSFX is not affiliated with or endorsed by Ensoniq or its owners.

## The screen (v1.1)

RSFX ships with an MPC screen skin in a rack layout: Input and Output modules with stereo peak meters and clip lights,
a display showing the algorithm and its actual signal chain, and Reverb, Delay, Modulation and Character modules.
`docs/previews/` has renders made from the plugin's real state (not photos of an MPC screen).

- **Module lights** show which blocks the current algorithm contains, the same blocks as the SIGNAL line.
- **Unused knobs** rest at zero with an empty ring and show `--`.
- **Borrowed knobs** carry a tag when a block from another module uses them, e.g. Damping reads `30 DLY` when it darkens
  a delay's repeats, and Balance reads `35 SEND` when it sets how much goes into the reverb or delay stage.
- **Bypass** is a true bypass: it returns the untouched input, before the Input trim.

The skin is generated by `tools/make_skin.py` and checked by `tools/check_skin.py`; `make preview PROGRAM=<n>` renders a
preview of any program.

## Knobs (Q-Links 1-16, in this order)

| # | Knob | What it does |
|---|---|---|
| 1 | Algorithm | Picks the effect. Turning it loads that effect's default settings, like selecting an effect on the hardware |
| 2 | Mix | Dry/wet, 0-100% |
| 3 | Decay | Reverb time (RT60). Gated reverb: gate hold. Reverse reverb: ramp length. Non-linear: duration |
| 4 | Damping | Reverb high-frequency damping, or delay feedback darkening |
| 5 | PreDelay | Reverb pre-delay, 0-500 ms |
| 6 | Delay | Delay time, 1-2000 ms |
| 7 | Feedback | Delay feedback, -99..+99 |
| 8 | ModRate | Chorus/flanger/phaser/tremolo/rotor speed |
| 9 | ModDepth | Modulation depth; VCF/wah envelope amount; pitch detune in cents |
| 10 | Drive | Distortion/amp drive, or EQ gain (-24..+48 dB) |
| 11 | Freq | Filter/EQ/wah/VCF frequency; flanger and phaser centre |
| 12 | Reso | Resonance/Q; flanger, phaser and chorus regeneration; compressor/expander ratio |
| 13 | Thresh | Compressor, gate, expander and trigger threshold |
| 14 | Pitch | Pitch shift, -12..+12 semitones |
| 15 | Balance | Send into the reverb/delay part of combination effects; R/L time ratio on dual delays |
| 16 | Output | Output level |
| 17 | Bypass | On screen, not on a Q-Link |
| 18 | Input | Input trim, -24..+12 dB, on screen. Kept when you change algorithm or program |
| 19-28 | (read-only) | Signal chain text, four meters, four module lights. They drive the screen and ignore writes |

v1.1 only appended parameters, so v1.0 projects and Q-Link assignments are unaffected.

Each knob belongs to at most one part of the current effect. A knob the current effect doesn't use shows `--`.
`docs/ALGORITHMS.md` lists, for every algorithm, its signal chain and which knobs are live.
The 98 algorithms are also exposed as programs (presets), each holding that effect's defaults.

## Build and install

From your phone, with no computer: see `GITHUB.md` (GitHub Actions builds, tests and publishes the zip; you
install it with Termius). From a computer with `g++-arm-linux-gnueabihf`: `make test && ./scripts/package.sh`.

## What's tested (here, on x86)

New in v1.1: `make compat OLD=<v1.0 x86 build>` compares against v1.0 on all 98 programs, twice (programs loaded fresh,
and a v1.0 project restored by parameter index). Every knob an algorithm uses holds the same value. 53 runs are
bit-identical or within float rounding (worst 76 dB below full scale). The rest differ in two expected ways, and
all of them match v1.0's level within 0.1 dB:
- **Delay fix:** algorithms with a delay block now hit the set delay time exactly. v1.0's delay-time glide stalled up to
  about 5 samples (0.1 ms) short, because the glide steps were too small to register in 32-bit float.
- **LFO phase:** in chorus, flanger, rotary, pitch and similar effects, v1.0's knob glide right after loading shifts the
  LFO phase, so the waveforms don't line up sample for sample even though the sound is the same. v1.1 jumps straight to
  the knob values when an algorithm loads, while the wet signal is faded out.

The original v1.0 tests:

`make test` loads the plugin through the VST2 entry point under ASan/UBSan and, for every algorithm: checks for
NaN/inf, clipping and dead output on drums, noise, a sine and silence; runs six random/extreme parameter sets at
odd block sizes; sweeps the Algorithm knob while audio plays; checks bypass is transparent; and measures reverb
RT60 against the Decay setting (1.0/2.5/5.0 s target → 1.02/2.41/4.90 s measured). Worst-case CPU is about 2% of
one x86 core. The installer is tested against a fake MPC filesystem.

## Known limitations

- **Not run on an MPC yet**, and the ARM binary is only built in GitHub Actions (no ARM compiler was available here).
- **Not tuned against hardware.** With recordings from a real unit (impulse responses, a sine sweep, a drum loop
  through each effect) the voicings can be matched much more closely.
- **ASR-10 bus routing is simplified.** On the ASR-10, each voice is sent to BUS1/BUS2/BUS3 with different wet/dry
  amounts. As an insert, RSFX runs everything through the full chain (the BUS1 path); Mix and Balance stand in for the rest.
- **No Effect Variations or effect modulation routing.** The hardware has four editable variations per effect and two
  mod sources each. On the MPC, use programs, Q-Links and automation instead.
- **Faithfulness varies by algorithm.** `docs/VERIFICATION.md` checks all 98 against the manuals. Names all match. Of the
  ASR-10's 50, 8 match the documented structure, 32 are partial (missing controls or different ranges) and 10 differ
  (e.g. CHOR+REV+DDL routing, PITCH+DDL's spiralling feedback, the four-band PARAM EQ). For the ASR-X, the User's Guide
  parameter pages were found for effects 01-24 only; 25-40 and the global reverbs remain unverified.
- **Ducker and Keyed Expander listen to their own input.** The manual documents them as left = signal, right = key,
  which an MPC insert could support by panning; RSFX doesn't do that yet.
- **Distortion curves are generic.** The ASR-X manual says there are five distortion curves and eight LFO shapes,
  but their names are in figures that didn't come through.
- **The 12 extra 44 kHz algorithms from the ASR-10 Version 2 O.S. disk aren't included yet** (44LUSH PLATE through
  44EQ+ROT+DDL). They're documented in the manual's appendix, PDF pp.367-375; see `docs/SOURCES.md`.
- **The skin hasn't been seen on an MPC.** It follows the same TUI.json format as the JV-880 skin and passes the static
  checks, but layout, fonts and touch behaviour are unverified on the device.
- **Live meters are unverified.** The meters are read-only parameters the plugin updates as audio plays. If MPC only
  redraws parameters when the host is told they changed, the meters will move only when the page refreshes. (The
  algorithm name, signal chain and module lights are announced to the host whenever the algorithm changes.)
- **Not possible in an MPC skin, so not included:** tooltips, undo/redo, resizing, per-module bypass (one algorithm runs
  as a single fixed chain), tempo sync and filter-mode switches (the engine has neither). Presets are the 98 programs
  plus the MPC's own plugin preset handling; state is saved with the project by MPC.
